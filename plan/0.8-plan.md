# SQLDesk 0.8.0 — Notebooks

Scope agreed with Iqbal on **2026-10-03**. Not started.

Everything in 0.8 points one way: **you should know what a thing costs before
it runs.** 0.7 made the heavy parts optional so an install pays nothing for
what it does not use; 0.8 does the same for a single query.

## The headline: notebooks

Everything in SQLDesk today ends in one SELECT. A notebook is for the work
that does not: pull this, join it to that, reshape it, look, then write the
result somewhere. People do that in Jupyter today and the warehouse never
hears about it — so the lineage, the permissions and the scheduling all stop
at the edge of somebody's laptop.

- Cells in **SQL and in Python**, each reading the last one's result, saved
  and re-runnable.
- Any cell's output available as a visualization or a dashboard widget.
- The parts SQLDesk already has — data source permissions, parameters, the
  scheduler, the result store — are most of what a notebook needs. What it
  adds is the chain.

Shape still to be designed. `CronScheduleDialog` was kept on purpose for this;
do not delete it as dead code.

## A cost model, before the query runs

Bytes scanned and an estimate of the work, from the engine's own planner,
shown as a number a person can refuse. MCP already refuses past a ceiling
(`SQLDESK_MCP_MAX_QUERY_COST`); this makes the ceiling visible rather than
something you discover by hitting it.

## MCP asks before it spends

An agent exploring should not quietly run a 4 TB scan because it seemed like a
reasonable next step. Past a threshold the tool returns the estimate and waits
for a person to say yes. Iqbal's words: *"every MCP ask should analyze and ask
user if he is okay with cost if it is crazy high."*

## An audit an administrator can read

Every execution is already recorded in `events`; nothing reads it as a
history. With it: who has been expensive this month, not just this hour.
Explicitly asked for on 2026-10-03.

## Per-data-source throttles and a kill switch

One person can queue fifty queries against the shared warehouse. And when a
warehouse is in trouble you want to stop sending it work without deleting the
data source.

## Prometheus metrics

StatsD is what SQLDesk emits, which is the wrong shape for most clusters now.
Queue depth, worker saturation and connection-pool use are the three that
matter. See [scale.md](scale.md).

## Cube: proven meaning moves out

Designed in `docs/0.7-plan.md` §7 and deliberately deferred. A measure that
has been agreed and used belongs in a semantic layer other tools can read, not
only in SQLDesk's. Three parts: an export a real Cube loads, asking rather
than guessing, and answering from Cube first where Cube already knows.

## Not in 0.8

Anything that would make SQLDesk call a model itself. MCP serves tools to a
client the user brings, and that stays true.
